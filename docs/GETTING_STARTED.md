# 启动与模型接入

需要 Node.js 22.13 或更高版本。项目使用 Node 内置 SQLite，开发与生产模式均为前后端同一端口。

```bash
git clone https://github.com/Liuziyu77/Strategy-RSI.git
cd Strategy-RSI
npm ci
npm run dev
```

打开 `http://localhost:3930`，点击“运行本地演示”即可观看本地策略对战。演示不需要模型 API。

## 接入自己的模型

在“玩家库”创建玩家，将控制方式选为“模型 API”，选择“自定义专属 API”，填写基础地址、API Key 和模型名称。接口需要兼容 `POST /v1/chat/completions`。保存后，在“新建对战”中邀请该玩家入座。

也可以配置共享服务：

```bash
cp .env.example .env
```

在 `.env` 中填入自己的配置：

```dotenv
API_BASE_URL=https://your-provider.example/v1
API_KEY=your-key
API_MODELS=model-a,model-b
```

共享服务在启动时读取；修改 `.env` 后重启服务。多个服务可使用 `.env.example` 中的 `PROVIDERS_JSON` 配置。密钥保存在服务端，修改专属 API 时留空表示继续沿用，不会回显到玩家查询中。

## 配置对战

1. 从玩家库选择 2–8 位不同玩家，设置总局数与并行数。并行数默认 1，不能超过总局数。
2. 选择每局随机身份，或手动交换身份后采用固定身份。多局座位轮换与身份分配独立。
3. 选择是否开启 Agent 聊天；实验参数中可设置随机种子、行动间隔、决策上限和聊天上下文条数。
4. 在观战页切换牌局、查看公开聊天与决策记录。暂停作用于整场；单步只执行当前所选局。

模型失败或返回非法动作时会重试一次，再使用同一可见输入的本地策略兜底；日志保存失败原因。唯一合法行动由系统直接执行，弃牌阶段一次选完需要弃置的卡牌。

## 经验的生成与使用

即时 RSI 在有选择的行动后反思；轮次 RSI 在整局结束后复盘。两者可单独启用、同时启用或全部关闭。关闭新增 RSI 后，已有经验仍会进入后续决策；若需要无经验对照，请使用不同的独立玩家档案。

同一玩家在并行局中完成的反思汇入自己的经验库，其他局的下一次决策可以读取。已经发出的请求保留原有输入快照。原始公开聊天只属于当前局，不跨局共享。

在“玩家库 → 个人经验”内按对战归纳多局经验。归纳调用该玩家当前配置的模型，分批整理后合并，原文与历史版本保留。后续优先使用最新有效归纳，并补充尚未覆盖的经验。归纳单批使用独立的 180 秒超时，暂时性失败可重试，失败任务再次发起时可复用匹配的成功批次。

## 生产与存档

```bash
npm run build
npm start
```

默认数据文件为 `data/arena.sqlite`。可通过 `DATA_DIR` 指定目录、`PORT` 指定端口、`HOST=0.0.0.0` 开放局域网访问，使用 `ARENA_ADMIN_TOKEN` 为管理操作启用令牌。

```bash
DATA_DIR=./data PORT=3930 HOST=0.0.0.0 npm start
```

重启后未完成对战恢复为暂停，点击继续可从检查点接着运行。同一数据目录只允许一个服务进程；测试或其他实例应使用独立目录。Git 默认忽略 `.env`、`data/`、`node_modules/` 与构建产物。

完整协议见 [API 文档](API.md)，实际支持的身份、卡牌与武将见 [规则范围](RULES.md)。
