# 启动与模型接入

Strategy-RSI 包含三国杀、狼人杀、国际象棋和中国象棋。先在游戏大厅选择游戏，再创建比赛；各游戏共用玩家库、模型服务、交流、RSI 和存档。

## 启动本地服务

需要 Node.js 22.13 或更高版本。项目使用 Node 内置 SQLite，开发与生产模式均为前后端同一端口。

```bash
git clone https://github.com/Liuziyu77/Strategy-RSI.git
cd Strategy-RSI
npm ci
npm run dev
```

若项目已有 `.runtime/node_modules/node/bin/node`，可用 `./run.sh dev`，脚本会优先使用项目内 Node。其他 npm 脚本也可用 `./run.sh <脚本名>` 执行。

打开 `http://localhost:3930`，进入 **游戏大厅**，通过游戏卡片或中英文名称搜索进入场地，再点击“运行本地演示”（英文场地为 “Run local demo”）。演示使用本地策略，关闭新增 RSI，不需要模型 API。切换游戏可点击顶部“游戏大厅”；返回场地会恢复该游戏上次的对战、对局、回放位置和视角。

## 配置模型玩家

在“玩家库”创建玩家，将控制方式选为“模型 API”，选择“自定义专属 API”，填写基础地址、API Key 和模型名称。例如，基础地址为 `https://your-provider.example/v1` 时，服务会请求 `POST /v1/chat/completions`。

也可以配置共享服务：

```bash
cp .env.example .env
```

```dotenv
API_BASE_URL=https://your-provider.example/v1
API_KEY=your-key
API_MODELS=model-a,model-b
```

共享服务在启动时读取；修改 `.env` 后重启服务。多个服务可使用 [.env.example](../.env.example) 中的 `PROVIDERS_JSON`。密钥保存在服务端，修改专属 API 时留空表示沿用，不会回显到玩家查询中。专属连接修改后生成新版本，已有比赛仍使用创建时的版本；共享服务配置以当前进程加载的配置为准。

为玩家选择 RSI 模式，再回到目标游戏的“新建对战”或“创建对战”中选择玩家。新游戏不使用玩家的“默认武将”字段，该字段只影响三国杀。玩家库等共享管理页目前为中文；狼人杀和国际象棋的场地、规则及 Agent 决策/交流/RSI 提示词支持中英文。

## 创建与控制比赛

| 游戏     | 人数 | 语言           | 身份 / 先手                          |
| -------- | ---- | -------------- | ------------------------------------ |
| 三国杀   | 2–8  | 中文           | 随机身份或手动固定身份，主公先行     |
| 狼人杀   | 6–12 | 中文 / English | 按种子分配固定角色组合，从第一夜开始 |
| 国际象棋 | 2    | 中文 / English | 白先黑后，多局默认轮换颜色           |
| 中国象棋 | 2    | 中文           | 红先黑后，多局默认轮换颜色           |

1. 在场地选择新比赛语言，然后打开创建对战面板，选择不同的玩家档案。语言在创建后固定，切换语言选择器不会翻译旧比赛。
2. 设置总局数、并行数和随机种子；并行数默认 1，不能超过总局数。只有三国杀提供固定身份配置。狼人杀角色配比见[规则](games/werewolf.md)。
3. 选择是否开启 Agent 交流。狼人夜间交流仅队内可见，其他游戏的发言公开；关闭交流不影响合法行动。
4. 开始比赛后，可切换局号、观战视角、事件、聊天和回放。暂停/继续作用于整场，单步只推进当前所选局。切换游戏页面不会暂停正在运行的比赛。

模型失败或返回非法动作时会重试一次，再使用同一可见输入的本地策略兜底；日志保存失败原因。唯一合法行动通常由系统执行；狼人杀讨论回合即使只有 `speak` 一个动作，也会请求 Agent 发言。达到决策上限会以实验性平局结束，原因与规则和棋分别记录。API 还支持超时、上下文窗口、座位轮换等实验参数，详见 [API](API.md)。

“比赛/对战”（match）可以包含多“局”（game）；“回放帧”（seq）是事件序号，不是走子数或模型决策次数。完整界面操作见[观战指南](ARENA_UI.md)。

## 经验的生成与使用

即时 RSI 在需要 Agent 决策的行动提交后反思；“轮次 RSI”指整局结束后的赛后复盘，不是每个白天或每步棋。两者可单独启用、同时启用或全部关闭。本地策略或外部 Agent 若开启 RSI，也需要为该玩家配置可用模型。

经验按 **Agent ID × 游戏类型** 隔离，中英文同一游戏共享经验。同一玩家在并行的同类游戏中完成反思后，后续决策可以读取新增经验；已经发出的请求保留原有输入快照。原始聊天只属于当前局，且遵循玩家的可见范围。关闭新增 RSI 仍会读取已有的同游戏经验；无经验基线应使用独立空经验玩家。

在游戏场地的“经验”面板中添加经验会自动绑定当前游戏。在“玩家库 → 个人经验”中，先选择“经验所属游戏”，再手动保存或导入 TXT。JSON 导入保留每条 `gameType`；未标记的旧 JSON 默认三国杀。导出包含该玩家全部游戏的经验及其游戏类型。

按对战归纳多局经验时，系统调用玩家当前配置的模型，分批整理后合并，原文与历史版本保留。后续优先使用最新有效归纳，并补充尚未覆盖的经验。单批使用独立的 180 秒超时，暂时性失败可重试；失败任务再次发起时可复用匹配的成功批次。

## 生产运行与存档

```bash
npm run build
npm start
```

默认数据文件为 `data/arena.sqlite`。可通过 `DATA_DIR` 指定目录、`PORT` 指定端口、`HOST=0.0.0.0` 开放局域网访问。`ARENA_ADMIN_TOKEN` 保护管理写操作；观战与导出接口供受信任实验者使用，包含全知信息，并非面向不可信 Agent 的隔离边界。外部 Agent 应使用带座位令牌的接口，见 [API](API.md#外部-agent)。

```bash
DATA_DIR=./data PORT=3930 HOST=0.0.0.0 npm start
```

重启后未完成比赛恢复为暂停，点击继续可从检查点运行。同一数据目录只允许一个服务进程；测试或其他实例应使用独立目录。升级前停止服务并备份整个数据目录，具体见[迁移说明](MIGRATION.md)。Git 默认忽略 `.env`、`data/`、`node_modules/` 与构建产物。
