# 项目质量检查记录

检查日期：2026-09-16。范围：当前多游戏工作区的规则引擎、公共调度、SQLite 持久化、Agent/RSI 可见上下文、经验隔离、游戏切换与回放、文档。以下为本次检查记录，不代表持续更新的质量认证。

## 结论

游戏规则和公共运行层已有清晰分工，具备研究平台所需的恢复、追踪和模拟模型验证能力。现有测试覆盖四种游戏的主要流程，但新增游戏之后，旧前端和旧文档的适配存在遗漏。本次发现并修复了初始化原子性、回放画面与导航状态一致性、经验归属等问题。未修改真实实验数据库，也未调用付费模型服务。

## 验证方式

使用 Node.js 22.20.0、项目锁文件依赖和本地 Chromium。单元/集成测试使用临时 SQLite 与模拟模型；浏览器测试使用独立服务和临时目录。

本次结果：类型检查通过；10 个测试文件、162 项单元/集成测试通过；27 项浏览器测试完整通过，最后的终局原因调整后补跑三国杀回放回归也通过；生产构建、格式与 `git diff --check` 通过。19 份 Markdown 的 184 个相对文件链接目标均存在。

```bash
./run.sh typecheck
./run.sh test
./run.sh build
./run.sh format:check
CHROMIUM_PATH=/path/to/chrome E2E_PORT=43931 ./run.sh test:e2e
git diff --check
```

若本机代理转发了回环请求，先为 localhost 配置 NO_PROXY/no_proxy，或在浏览器测试命令中取消代理变量。README 与 docs 下 Markdown 的相对文件链接也检查其目标存在；该检查不验证外部网站和标题锚点。

## 后续维护项与验证边界

1. **前端职责仍集中。** `web/main.tsx` 与 `web/MultiGameArena.tsx` 均超过千行，分别维护刷新、创建、回放和错误状态；本次回放问题说明两套逻辑可能继续偏离。下一步适合提取公共观战请求/帧校验 hook，并拆分创建面板与经验面板。
2. **类型与自动检查仍有缺口。** 存储和旧前端还有 `any`，根 tsconfig 未包含 tests，Vitest/Playwright 执行不等于测试代码通过 TypeScript 静态检查。当前没有仓库内 CI 工作流；本次通过是本地验证结果。建议后续增加测试专用 tsconfig，并将类型、单元、构建和关键浏览器检查放进 CI。
3. **规模验证有限。** 比赛列表没有分页，旧应用周期性读取全部玩家经验；每个事件保存完整压缩状态，同步 SQLite 和棋局历史重建可能在长期、大并行实验中成为瓶颈。本次未做大库压测或长时稳定性验证，不给出并行吞吐承诺。
4. **部署与规则边界保持明确。** 管理令牌只保护写操作，观战/导出含全知信息，适合受信任实验环境。国际象棋使用 chess.js 的子力判和，未穷举罕见死局；中国象棋不实现长捉/将捉混合竞赛裁定。详细范围见[游戏目录](games/README.md)。
5. **不评价真实模型棋力或 RSI 收益。** 模拟模型验证协议、隔离、记忆写入与复用；真实模型质量、费用、供应商兼容性和 RSI 效果需要单独实验。本次也未执行依赖漏洞数据库审计。
