# 三国杀四模型基线实验

[项目首页](../../README.md#基线实验) · [实验目录](../README.md) · [English](README.en.md) · [数据](results.json) · [对局与聊天](#历史对局与聊天) · [图表](assets)

本次实验先测量空经验 Agent 的表现，为后续 RSI 对照提供起点。固定排程共 **528 局**，其中 **489 局正常结束、39 局异常**，没有平局。结果于 2026 年 9 月 14 日完成汇总。

## 实验设置

| 项目          | 设置                                                                                            |
| :------------ | :---------------------------------------------------------------------------------------------- |
| 模型 API 标签 | `bailian/deepseek-v4-flash`、`glm-5.2`、`kimi-k3`、`qwen3.8-max-0902`                           |
| 武将与经验    | 全部关羽；RSI 关闭；个人经验为空；公开聊天开启                                                  |
| 双人局        | 6 种配对 × 20 个发牌种子块 × 2 次身份与座位镜像；计划 240 局，正常 233 局，异常 7 局            |
| 四人身份局    | 12 个种子块 × 24 种模型座位排列；身份座位模板随块轮换；计划 288 局，正常 256 局，异常 32 局     |
| 身份          | 双人：主公、反贼；四人：主公、忠臣、反贼、内奸各一位                                            |
| 请求参数      | 温度 0.6，输出上限 4,096 Token；最近 300 条游戏事件、最多 80 条聊天                             |
| 并发与重试    | 最多 128 局并行；每模型最多 32 个请求并发；每请求超时 90 秒；每次决策最多 3 次尝试              |
| 终止与兜底    | 引擎决策达到 1,800 次记平局；决策重试耗尽记异常；不使用本地策略替模型决策；唯一合法动作自动执行 |

使用项目原规则和决策提示词。四模型应用相同的等价协议适配：仅当 `cardIds` 完整重复合法动作已绑定的卡牌、且该动作没有额外选牌要求时，移除冗余字段；不改动作、目标或真实选牌。正式结果衡量适配后的表现，不等于未经适配的接口合法率。连通性、并发压测、先导实验和恢复服务检查均不计入这 528 局。

## 六张图的统计口径

| 图表           | 计算方式与范围                                                                                                                                                               |
| :------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Win rate       | 胜场 / 正常结束的参战局数，两个赛制分开；异常局不进入分母。误差线为 20,000 次种子块 bootstrap 的 95% 百分位区间。                                                            |
| Head-to-head   | 行模型对列模型的双人局胜率；每种配对正常结束 36–40 局。对角线未进行同模型自对战，留空。                                                                                      |
| Role win rate  | 四人局按身份分组的胜场 / 正常参战局数。主公与忠臣按阵营共同获胜，已阵亡队员仍可计胜，因此各模型胜率之和不必为 100%。                                                         |
| Game duration  | 正常结束对局的 `durationMs`，转换为分钟；保留排队、重试时间，扣除明确记录的账户恢复暂停。大圆点是中位数，粗线是第 25–75 百分位，须线是第 5–95 百分位；散点展示全部正常对局。 |
| Token use      | 累加正式请求返回的输入、输出 `usage`，包括有用量记录的失败和重试。共 30,342 条请求记录，28,587 条返回用量；没有 `usage` 的请求不补估。                                       |
| Chat frequency | 正常对局中，包含公开发言的模型决策数 / 模型决策数；排除唯一合法动作的自动执行。它是每次决策的发言比例，不是每分钟消息数。                                                    |

图表使用相同模型顺序与配色，热力图固定在 0–100%。SVG 将字体转为路径，避免依赖阅读设备的字体；PNG 宽度为 2,816 像素。读取精确值、区间和各身份样本量可使用 [results.json](results.json)。

## 怎样解读结果

**四人身份局支持 DeepSeek 的优势，但不能把其他三者排成确定顺序。** DeepSeek 为 158/256（61.7%），GLM 为 74/256（28.9%），Kimi 为 86/256（33.6%），Qwen 为 78/256（30.5%）。对同一种子内的模型结果配对重采样，对全部六组比较做 Bonferroni 校正后，只有 DeepSeek 与其他三者的差值区间全部高于 0。

| 四人局比较      | 胜率差 / 百分点 | 校正后的区间 / 百分点 |
| :-------------- | --------------: | --------------------: |
| DeepSeek − GLM  |           +32.8 |        +24.2 至 +42.0 |
| DeepSeek − Kimi |           +28.1 |        +15.7 至 +40.8 |
| DeepSeek − Qwen |           +31.2 |        +23.2 至 +40.9 |
| GLM − Kimi      |            −4.7 |         −12.2 至 +2.7 |
| GLM − Qwen      |            −1.6 |         −11.5 至 +7.0 |
| Kimi − Qwen     |            +3.1 |         −7.3 至 +12.5 |

以上是约 99.17% 单组覆盖的校正区间；上方胜率图的误差线则是单模型 95% 描述性区间，不能用两条误差线是否重叠代替配对检验。双人局中，DeepSeek 对 GLM 仅为 20 : 19，其配对胜率区间为 38.5%–64.1%，目前不足以判断这组交锋谁更强。

**异常局需要单独看。** 异常集中在哪些模型或牌局可能影响正常样本的比较。即使把四人局的 32 个缺失结果全部设为「DeepSeek 负、所比较对手胜」，用原计划 288 局作分母，DeepSeek 仍分别领先 GLM、Kimi、Qwen 至少 18.1、13.9、16.7 个百分点。这是缺失结果的保守界限，不是置信区间，也不能消除其他不确定性。

**时长、Token 和聊天各回答不同问题。** 四人局中位时长 36.2 分钟，约为双人局的 3 倍，但包含本次运行中的排队与重试，不能据此推算单局独占 API 时的速度。输入占已报告 Token 的 94.1%，值得检验上下文压缩；请求次数、上下文、输出策略和供应商计数方式共同影响总量，较少 Token 不直接等于较高决策效率或更低费用。GLM 的四人局发言比例为 96.6%，高于 DeepSeek 的 82.3%，却没有对应更高胜率；当前观测不能识别聊天的因果效果。

**这组成绩还没有检验 RSI。** 四人局仅有 12 个独立种子块，双人局每对 20 个；镜像和座位排列增加局数，但不是同等数量的独立环境。结论限定于这些 API 模型标签、关羽、规则和提示词，不能外推为通用模型能力排名。下一步可固定基础模型与对手，在未用于积累经验的新种子上比较空经验、归纳后冻结经验和持续 RSI，并将经验生成用量与测试用量分开。

## 历史对局与聊天

**528 局 · 66,041 条行动 · 245,305 条事件 · 24,352 条公开发言**，按赛制拆为两份：

| 文件                                                | 对局数                        |    大小 |
| :-------------------------------------------------- | :---------------------------- | ------: |
| [双人局历史与聊天](games-history-duel.json)         | 240 局：233 局正常、7 局异常  | 18.5 MB |
| [四人身份局历史与聊天](games-history-identity.json) | 288 局：256 局正常、32 局异常 | 47.8 MB |

每份文件都是可独立读取的 JSON 对象，合计包含全部正式实验对局：489 局正常结束、39 局异常终止。`partition` 标明赛制与分片编号；`counts`、`countsBySuite` 和 `eventTypeCounts` 只统计当前文件，原始回放核验信息对应整批实验。每局独立保存模型、玩家身份、胜负、时间、轮次、行动、事件、聊天和终止时状态。先导实验与中间检查点不重复导出。

| 字段                             | 内容                                                                                                  |
| :------------------------------- | :---------------------------------------------------------------------------------------------------- |
| `experiment`、`source`、`counts` | 模型与实验设置、来源校验值、总体记录数；`countsBySuite` 按赛制统计。                                  |
| `games[]`                        | 一局一项，以 `id` 关联 `results.json`；`status` 区分 `finished` 与 `error`。                          |
| `games[].players`                | 座位、名字、模型、武将、身份、终局体力、卡牌与获胜标记；异常局的 `won: false` 不代表实际判负。        |
| `games[].actions`                | 原始已执行决策，包括行动 ID、选牌、决策理由、可选发言，以及 `llm` / `forced` 来源。                   |
| `games[].events`                 | 原始完整事件序列，包括出牌、伤害、摸牌、死亡和公开聊天；保留 `seq`、时间与可见性字段。                |
| `games[].chat`                   | 单独整理的公开聊天：发言座位、名字、模型、身份、时间、轮次、阶段与消息原文；`eventSeq` 指向对应事件。 |
| `games[].finalState`             | 存档终止时的引擎状态；异常局保留失败前状态，不补造胜负。                                              |

文件用于赛后分析，含隐藏身份和私有卡牌事件；给某位 Agent 重建可见上下文时，需要按 `privateTo` / `publicText` 等信息过滤。`chat` 是 `events` 中聊天的便捷视图，两者不要重复计数。`durationMs` 扣除明确记录的暂停，`wallDurationMs` 保留跨暂停的总历时。

导出保留原始行动和事件，聊天文字来自引擎实际记录的公开发言。文件不包含 API 密钥、地址、请求头、重复决策提示词或原始 API 响应。

```python
import json
from pathlib import Path

folder = Path("exp/sanguosha")
for filename in ["games-history-duel.json", "games-history-identity.json"]:
    with (folder / filename).open(encoding="utf-8") as stream:
        data = json.load(stream)
    game = data["games"][0]
    print(game["id"], game["status"], game["winner"])
    for message in game["chat"]:
        print(message["round"], message["model"], message["message"])
```

如需从原始存档重新导出，在仓库根目录运行（仅用 Python 标准库，不调用模型 API）：

```bash
python exp/sanguosha/export_history.py --source /path/to/sanguosha/exp
```

`--source` 目录需包含原始 `plan.json`、`data/summary.json` 和 `games/*.json.gz`。默认在 `exp/sanguosha/` 生成 `games-history-duel.json` 和 `games-history-identity.json`，可用 `--output-dir` 指定其他目录。

## 数据与重绘

[公开数据](results.json)包含汇总指标、528 局的身份与结果、时长、统计区间和源文件 SHA-256。它不含 API 地址、密钥、模型原始对话或私人经验。原实验已回放核验 528 份最终记录、66,041 条行动和 30,342 次模型输入；公开汇总保留核验计数，但不代替完整轨迹审计。

在仓库根目录运行：

```bash
python -m venv /tmp/strategy-rsi-figures
/tmp/strategy-rsi-figures/bin/python -m pip install -r exp/sanguosha/requirements.txt
/tmp/strategy-rsi-figures/bin/python exp/sanguosha/render_figures.py
```

脚本只读取本地 JSON，输出六张 SVG 和六张高清 PNG 至 `exp/sanguosha/assets/`，不调用模型 API。它复现可视化，不重新估计源分析中已有的 bootstrap 区间；时长散点的纵向错位使用固定随机种子，仅为减少遮挡。
